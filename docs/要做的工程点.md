1. P0：事件驱动增量入库——下一阶段
- PostgreSQL 持久入库任务表：文件标识、版本/哈希、状态、尝试次数、错误和处理时间。
- 独立 worker 消费任务。
- 上传保存后创建任务、返回任务 ID，前端查询进度和结果。
- 任务领取、处理租约、超时、失败重试和重启后回收过期任务。
- 同文件事件合并、防抖、哈希幂等、文件写入稳定检测和版本检查。
- watchdog 监听文件新增、修改、重命名和删除。
- 启动及定期对账，补偿漏事件；保留全量扫描作为初始化与补偿入口。
- 磁盘文件删除后，通过任务同步删除对应向量。
- 文档清单从 SQLite 迁移到 PostgreSQL，核对旧记录、磁盘版本与 Milvus 块数。
- 安全更新文档：新版本准备完成后切换，再清理旧版本；处理 PostgreSQL 与 Milvus 跨库失败。
- 多 worker 同文件互斥、重复任务重放、新旧版本乱序处理；必要时再引入 Redis/Celery。

- 配置化模型、知识库和数据目录，替换散落的绝对路径。
- 同步 README、quickstart、结构说明、模块说明和兼容依赖。
- 验证全新环境安装。
- 清理注释旧实现、重复文件/入口和生成图片路径。
- 检查 API 导入时初始化服务、绘图等副作用。
- PostgreSQL、Milvus、模型依赖就绪检查，区分进程存活与服务可用。
- 全局锁改为按会话、文件控制并发，保证问答读取有效文档版本。
- 模型超时、重试、连接池、资源关闭和错误分类。
- 日志增加请求 ID、任务 ID。
- PostgreSQL/Milvus 备份恢复、数据卷管理和数据对账。

4. P2：记忆完善——本阶段暂缓
- 自动提取改为持久后台任务，支持重试、限流及积压控制。
- 摘要后台化，处理超长单轮、历史积压和上下文总预算。
- 验证摘要覆盖边界、重复处理、漂移和失败恢复。
- 记录失败/中断消息，增加请求幂等和同会话并发顺序控制。
- 自动记忆开关、来源展示和错误记忆纠正。
- 语义去重、冲突更新、修改接口和版本管理。
- 自然语言“修改／忘掉”操作。
- 背景事实按问题检索，概况与详情分层读取。
- 验证自动提取、跨会话偏好及删除效果。
5. P2：检索与回答——按需选择
- 优化混合召回数量、RRF、过滤策略和干扰文档处理。
- 按需要引入真正的 reranker。
- 稳定 chunk 标识和引用追溯。
- 核对引用编号范围、逐句依据和数值条件。
- 相关性评分批处理、缓存及调用次数/耗时优化。
- 完善资料不足、联网来源可靠性、重试边界和失败回复。
- 按需实现流式回答，处理质量评分失败后的重试和草稿展示。
