# 个人知识库基础功能

本轮实现同步上传、同名更新、删除和用户检索隔离。每个用户一个逻辑知识库；不新增 Celery 文档任务、目录监听或完整版本管理。

## 使用前准备

在项目根目录、rag0 环境执行新增迁移，再重启 API：

```powershell
python -m alembic -c backend/alembic.ini upgrade head
```

迁移新增 `knowledge_documents`，不修改 Milvus schema，也不删除旧集合。本轮没有自动执行数据库升级。

可在 `backend/.env` 配置绝对路径 `KNOWLEDGE_DATA_DIR`；默认使用 `backend/datas/personal`。首次使用后不要直接改路径或移动文件，数据库和 Milvus 的来源路径需要配套迁移。

## 基础操作

- 上传：`POST /documents/upload`，multipart 字段 `file`。当前用户同名文件更新，不同用户同名文件独立。
- 更新：`PUT /documents/{document_id}/content`，仅更新当前用户名下文档，保留原文件名。
- 列表：`GET /documents`，只返回当前用户文档 ID、文件名、状态和块数。
- 删除：`DELETE /documents/{document_id}`，校验归属，先标记不可检索，再清理文件、向量和记录。清理失败保留 `deleting` 状态，可再次删除。
- 以上接口要求 Bearer 登录认证；他人文档返回 404。
- 页面上传支持同名更新，并提供带确认框的最小删除入口。

## 隔离与更新方式

PostgreSQL 保存用户归属、内容哈希、有效来源和块数。文件存储在用户 ID / 文档 ID / 随机快照名下。SHA-256 只处理本次上传，不遍历目录。

为兼容现有 Milvus schema，本轮使用 PostgreSQL 授权来源白名单，在向量搜索前加入 `source in [...]` 条件；未登记的历史共享来源、其他用户来源、候选来源及删除中资料不参与 API 本地检索。过滤条件逐请求传递，不修改全局检索器。

同用户写操作通过 PostgreSQL 事务级 advisory lock 串行；保留现有进程内 `graph_lock`。当前同步实现会在解析和写入期间持有事务，不宣称已完成细粒度并发优化。

更新先向独立快照来源写入，核对块数后提交有效来源，再尽力清理旧来源。写入失败不切换已发布来源；这不是 PostgreSQL 与 Milvus 的共同事务，也没有历史版本回滚页面。

## 历史资料和边界

- 旧共享资料及 SQLite 清单原样保留，不自动授予任何用户访问权限。由资料所有者登录后重新上传；本轮未自动迁移旧清单。
- API 使用 graph2 用户范围检索。graph2 无用户身份时不检索本地资料；旧命令行评测和直接共享检索工具属于运维入口，不适用于个人知识库权限验证。
- 历史全量重建会清空同一 Milvus 集合，影响个人文档；不要与个人知识库混用。重建后的自动清单失效处理仍待实现。
- 候选失败和旧来源清理失败可能留下不可检索的孤立文件/向量；自动清理及对账后续补充。首次上传失败且无已提交文档记录时，同样需要运维清理。
- 当前只核对块数，没有完整块指纹核验、跨进程检索快照、分页来源过滤或大规模白名单优化。
- 删除不会抹除历史聊天中已经保存的回答和引用。跨存储备份恢复、异步任务和目录同步仍在后续清单。

## 验证

在 `backend` 目录执行：

```powershell
python -m unittest tests.test_personal_documents -v
```

8 项离线测试已通过，使用 SQLite 和模拟解析/向量库，验证权限范围、API 拒绝越权、搜索前过滤、同名隔离、哈希跳过、更新发布、部分写入失败以及删除失败后重试。不能代替真实 PostgreSQL advisory lock、Milvus 混合检索和页面联调。
