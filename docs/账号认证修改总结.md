## 2. 数据模型与迁移

### `backend/memory/models.py`

`User` 新增：

- `username`：登录账号，唯一，允许为空以兼容旧开发用户。
- `password_hash`：保存密码哈希，允许为空；不保存明文密码。

新增 `AuthToken`，对应 `auth_tokens` 表：

- `token_hash`：原始令牌的 SHA-256 哈希，作为主键。
- `user_id`：所属用户，外键指向 `memory_users.id`，带查询索引。
- `expires_at`：带时区的过期时间。

账号 `username` 和显示名称 `name` 分开；显示名称可以使用中文。

## 3. 密码处理

`backend/memory/password.py`：

- `hash_password()`：生成 16 字节随机盐，用 scrypt 计算密码哈希。
- `verify_password()`：从保存结果中读取盐，用相同参数计算，再通过 `hmac.compare_digest()` 比较。
- 保存格式为 `scrypt$盐的十六进制$哈希的十六进制`。
- 使用 Python 标准库，无需为此安装第三方依赖。

盐用于密码哈希，不是登录令牌；同一密码多次保存可以产生不同的哈希结果。

## 4. 数据库操作层

### `backend/memory/repositories/user.py`

- 保留原 `create_user()`，但旧公开创建入口已停用。
- `create_registered_user()`：保存账号、显示名称和已计算好的密码哈希。
- `get_user_by_username()`：按账号查询用户，未找到返回 `None`。

### `backend/memory/repositories/token.py`

- `create_token()`：保存令牌哈希、用户 ID 和过期时间。
- `get_token()`：按哈希查找令牌。
- `delete_token()`：撤销指定令牌；记录不存在时不报错。

这些函数负责数据库操作，事务提交由调用方管理。新认证代码直接导入对应模块，不需要扩充旧 `repository.py` 兼容入口。

## 5. 认证路由

`backend/auth_api.py` 使用 `APIRouter(prefix="/auth")`：

| 接口 | 处理逻辑 |
|---|---|
| `POST /auth/register` | 校验账号、名称、密码；账号统一小写；保存密码哈希；账号冲突返回 409 |
| `POST /auth/login` | 查询账号并校验密码；发放随机令牌；数据库只保存令牌哈希 |
| `GET /auth/me` | 认证后返回当前用户 ID、账号、显示名称 |
| `POST /auth/logout` | 删除传入令牌的数据库记录，重复退出也可返回成功 |

注册账号为 3～64 位英文字母、数字或下划线；显示名称为 1～100 个字符且不能全为空白；密码为 8～128 个字符且不能全为空白。账号大小写不区分。

登录使用随机令牌，有效期为发放后的 24 小时。每次成功登录生成新令牌；每次业务请求重复使用已有令牌，不重新发放。退出使当前令牌立即失效，其他设备的令牌不受影响。

不存在的账号也会执行一次虚拟密码哈希校验，以减少响应耗时差异。接口不返回密码哈希。

## 6. 根据令牌识别用户

`backend/memory/authentication.py` 的 `require_user_id()`：

1. 使用 `HTTPBearer` 读取 `Authorization: Bearer <令牌>`。
2. 拒绝未提供令牌或令牌长度异常的请求。
3. 对原始令牌计算 SHA-256，查询数据库。
4. 检查令牌是否过期、所属用户是否存在。
5. 成功时返回用户 UUID；失败返回 401。

业务接口通过以下参数取得身份：

```python
user_id: UUID = Depends(require_user_id)
```

认证解决“是谁”；原有数据库操作中的归属检查解决“能否操作这个会话或记忆”。两者都保留。

## 7. 业务 API 接入

`backend/api.py`：

- 导入认证路由，并调用 `app.include_router(auth_router)`。
- 新建会话、重命名会话、问答、保存记忆的请求模型移除 `user_id`。
- 以下接口的用户 ID 改为通过认证依赖取得：

| 模块 | 已接入的操作 |
|---|---|
| 会话 | 列表、新建、重命名、删除、导出、历史读取 |
| 长期记忆 | 保存、列表、删除 |
| 问答 | 普通问答与“记住：”分支 |
| 上传 | 登录后才能上传，当前仍写入共享知识库 |

`save_explicit_preference()` 显式接收认证后的 `user_id`；历史读取、消息保存、偏好读取和后台提取都沿用该身份。

旧 `POST /memory/users` 和 `GET /memory/users/{user_id}` 返回 410，停用凭用户 ID 创建或恢复开发身份的公开入口。基础 `/health` 仍无需登录。

## 8. 前端接入

`frontend/app.py` 主要变化：

- `auth_token`：在当前 Streamlit 会话中保存原始令牌。
- 初始化时，没有令牌就清除旧的开发用户身份及聊天状态。
- `auth_headers()`：组装 Bearer 请求头。
- `api_request()`：合并请求头，自动携带令牌，并调用过期处理。
- 上传和问答的直接 `requests.post()`：单独添加令牌请求头和过期处理。
- `clear_login()`：清除令牌、用户、当前会话、消息、会话列表和部分操作状态，不删除数据库数据。
- `handle_auth_expired()`：持有令牌的请求返回 401 时清除身份、重新运行页面并显示登录失效提示。
- 侧边栏：替换旧用户入口，提供注册、登录、退出；登录先保存令牌，再加载会话。
- 注册提供确认密码；密码输入使用隐藏显示。
- 登录失败的 401 正常显示错误，不当作已有登录过期。
- 清理业务请求中多余的 `user_id`；页面内部用户 ID、菜单状态和用户专属 widget key 继续保留。

令牌仅保存在当前页面会话内；页面会话丢失后需要重新登录，数据库历史仍保留。过期是在请求返回 401 时处理，不是页面静置时自动倒计时退出。
